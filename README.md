# blake3-kmp

Kotlin Multiplatform bindings for BLAKE3, backed by JNI, with a separate JVM Foreign Function & Memory API (FFM) alternative.

## Published modules

The KMP coordinates publish Gradle Module Metadata that routes consumers to a platform-specific artifact. All artifacts use the group `com.akhsaul.blake3` and are published to GitHub Packages at `https://maven.pkg.github.com/akhsaul/blake3-kmp`.

| KMP coordinate | Android target artifact | JVM target artifact | Native payload |
| --- | --- | --- | --- |
| `com.akhsaul.blake3:blake3-kmp:<version>` | `blake3-kmp-android` | `blake3-kmp-jvm` | Single Android AAR with `arm64-v8a`, `armeabi-v7a`, `x86_64`, `x86` in `jni/` (devices and emulators; Play App Bundles strip unneeded ABIs per device) plus desktop host-test libraries under `/native-host/*` in `classes.jar` (`aarch64` + `amd64`; Linux `.so` stored as `.so.bin` because AGP strips `*.so` from Java resources). Desktop JVM JAR: host libraries in `aarch64` and `amd64` resource paths (`amd64` includes macOS x86_64) |
| `com.akhsaul.blake3:blake3-ffm:<version>` | — | `blake3-ffm` | JVM 22+ FFM implementation |

Use a release tag without its `v` prefix as the version: tag `v0.4.1` publishes version `0.4.1`. The default local version is `0.1.0-SNAPSHOT`.

## Consume with Gradle

Add the GitHub Packages repository to dependency resolution, for example in `settings.gradle.kts`:

```kotlin
dependencyResolutionManagement {
    repositories {
        maven {
            url = uri("https://maven.pkg.github.com/akhsaul/blake3-kmp")
            credentials {
                username = providers.gradleProperty("gpr.user").orNull
                    ?: System.getenv("GITHUB_ACTOR")
                password = providers.gradleProperty("gpr.key").orNull
                    ?: System.getenv("GITHUB_TOKEN")
            }
        }
        mavenCentral()
    }
}
```

Add the multiplatform coordinate to common code as usual; Gradle selects `blake3-kmp-android` for Android runtime and `blake3-kmp-jvm` for desktop JVM:

```kotlin
dependencies {
    implementation("com.akhsaul.blake3:blake3-kmp:<version>")
    // JVM 22+ alternative: implementation("com.akhsaul.blake3:blake3-ffm:<version>")
}
```

### Android `androidHostTest` on a desktop JVM

An Android host test is compiled in an Android source-set context, so Gradle selects the Android AAR for its runtime classpath — even though the test executes on the desktop JVM, where `System.loadLibrary` cannot resolve it. The AAR therefore bundles desktop libraries under `/native-host/*` in `classes.jar`, and the Android loader (`AndroidBlake3.kt`) tries `System.loadLibrary` first, then extracts `/native-host/<arch>/<lib>` (`<lib>.bin` fallback for Linux, since AGP strips `*.so` from Java resources). Host tests pass with no manual extraction and no Gradle substitution.

### Exclude host-test natives from Android apps

`/native-host/*` is test-only payload. Strip it when packaging an Android app:

```kotlin
android {
    packaging {
        resources {
            excludes += setOf("/native-host/*")
        }
    }
}
```

GitHub Packages requires credentials to download packages. For local builds, set `gpr.user` and `gpr.key` in `~/.gradle/gradle.properties`, or provide `GITHUB_ACTOR` and `GITHUB_TOKEN` as environment variables. A personal access token (classic) for package consumption needs the `read:packages` scope; do not commit it. In GitHub Actions, a consumer's `GITHUB_TOKEN` can read the package if that repository has package access. See [GitHub's Gradle registry authentication guide](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-gradle-registry#authenticating-to-github-packages).

## Local build and publication

Native libraries are generated by `VERSION=0.4.1-SNAPSHOT ./build-package` (requires Zig 0.16.0 and `ANDROID_NDK_HOME`). It builds all four Android ABIs into `src/androidMain/jniLibs`, the desktop JVM libraries into `src/jvmMain/resources/jni` (copied to `blake3-ffm`), and the Android host-test payload into `src/androidMain/resources/native-host` (desktop `aarch64` + `amd64`, Linux `.so` renamed to `.so.bin`). A full Android publication also requires an installed Android SDK. Override the local version with `-Pversion=0.4.1-SNAPSHOT` when publishing directly with Gradle.

`./gradlew publishToMavenLocal` publishes all modules locally without GitHub credentials. For formatting and static checks that skip native-dependent tests, use:

```sh
./gradlew spotlessCheck check -x testAndroid -x testAndroidHostTest -x jvmTest -x androidConnectedCheck -x test
```

The CI workflows build the full Android ABI set and the shared desktop JNI payload. Emulator tests run on x86 (API 27) and x86_64 (API 36) against `:blake3-kmp`. A dedicated host-test job runs `testAndroidHostTest` and `testAndroid` with no manual native setup, and the publish job asserts the AAR carries all four ABIs plus the `/native-host/*` host-test payload in `classes.jar`.
